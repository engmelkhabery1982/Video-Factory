MILESTONE 3 - LOCAL GEMINI VERIFICATION (WINDOWS, POWERSHELL)
=============================================================

Read PROVIDER_SETUP_AR.md first. Your key is sent only to Google's
generativelanguage endpoint. The script never prints it, never writes it to a
file, and redacts every output it saves.

The script runs the SAME services the app uses (plan job, speech preview job,
draft conversion, budget ledger, evidence binding). Generated output goes to
an isolated QA folder that you choose with --qa-root. It is never data\ or
output\ of the repository.

A. ONE-TIME SETUP (repository root)
-----------------------------------
  1. Node.js 18 or newer is required (Node 20+ recommended).
  2. npm ci --ignore-scripts
  3. npm run build:core
  4. Confirm the core build exists:  dir packages\core\dist\index.js

B. CHOOSE ONE QA FOLDER FOR THE WHOLE SESSION (outside the repository)
----------------------------------------------------------------------
  $qa = "C:\buildtrack-qa\m3-session-1"
  Use the SAME folder for every step. The budget ledger lives inside it.
  Deleting it resets the ledger, which is a bypass. Do not do that.

C. SET THE KEY FOR THIS WINDOW ONLY (paste it yourself; never paste it into chat or a file)
-------------------------------------------------------------------------------------------
  $env:GEMINI_API_KEY = "<paste your key here>"

D. STEP 1 - PREFLIGHT (read-only; no generation)
------------------------------------------------
  node --import tsx tools/gemini-verify.mjs --qa-root $qa --preflight

  Expect JSON with:
    "catalogHttpStatus": 200, "catalogReachable": true
    "binding": "current"  (the record is bound to this key's fingerprint and the models)
    "capability": "live_test_unverified" until a generation succeeds
  This proves CATALOG access only. It does not prove quota, free tier, or generation.
  "catalogReachable": false means the network or the key is the problem.

E. STEP 2 - ONE TEXT PLAN (only after you confirm a free-tier key with a budget limit)
-------------------------------------------------------------------------------------
  $env:GEMINI_GENERATION_ENABLED = "1"
  $env:GEMINI_FREE_TIER_CONFIRMED = "1"
  node --import tsx tools/gemini-verify.mjs --qa-root $qa --text --confirm-free-tier

  Uses a fixed built-in fixture brief. No project file is read or sent.
  At most 2 text previews per session. The app's ledger counts every attempt.
  On success it creates a draft from the plan (three treatments) and prints the
  draft id and treatment names. Expect "status": "succeeded" and "draftHttpStatus": 201.
  This is a successful provider call. It is NOT listening review and NOT owner approval.

F. STEP 3 - ONE SPEECH PREVIEW (reviewed text only, 20 seconds at most)
-----------------------------------------------------------------------
  1. Write ONE short line you have reviewed to a file, 350 characters at most:
       notepad reviewed-line.txt
     Save it. Do not put private or unreviewed material in it.
  2. Run:
       node --import tsx tools/gemini-verify.mjs --qa-root $qa --speech --confirm-free-tier --reviewed --text-file reviewed-line.txt --language en --voice Kore
  3. For Arabic, use --language ar and text that contains Arabic letters, with the
     diacritics you reviewed. Arabic readiness is a SEPARATE evidence state. An English
     run does not prove Arabic.
  4. At most 2 voice previews per session.

G. LISTEN, THEN RECORD
----------------------
  The WAV is in <qa>\output\gemini-verify\. Listen to it yourself.
  The script does not judge audio quality. Listening review is a separate step
  from the provider call, and owner approval is a separate step again.
  Evidence files are in <qa>\evidence\ (JSON, redacted, hashes and durations only).

H. STOP AND CLEAN UP
--------------------
  Remove-Item Env:GEMINI_API_KEY
  Remove-Item Env:GEMINI_GENERATION_ENABLED
  Remove-Item Env:GEMINI_FREE_TIER_CONFIRMED

I. WHAT A FAILURE MEANS
-----------------------
  401  key rejected                 -> check the key value. Stop. No fallback is used.
  403  access refused               -> check the project and the model access. Stop.
  429  quota or rate limit          -> stopped; no fallback. Wait, or check the free-tier limit.
  0 / network / timeout             -> try later. Nothing was saved as success.
  STOP: ...                        -> a gate stopped the run BEFORE any call.
  "status": "failed" with a code   -> the job failed and was not adopted; see "failure".

J. DO NOT COMMIT
----------------
  Do not add reviewed-line.txt, WAV files, evidence files, or the QA folder to Git.
  Commit source, tests, and docs only.

K. OWNER UI WALKTHROUGH (ContentPlan, same QA folder, live only after D and E pass)
-----------------------------------------------------------------------------
  The page reads its server state from the QA data folder, never from your owner data\ or output\.

  1. npm run build
  2. $env:BUILDTRAKE_DATA = "$qa\data"
     $env:BUILDTRAKE_OUTPUT = "$qa\output"
     $env:GEMINI_GENERATION_ENABLED = "1"      (only after you confirm a free-tier key with a budget limit)
     $env:GEMINI_FREE_TIER_CONFIRMED = "1"
     npm start                                   (then open http://localhost:3000)
  3. Open "Content plan" in the top bar. Choose "Gemini (explicit)".
     The panel shows the capability state and the reason Generate is off, if it is off.
     Nothing calls Google on page load, typing, saving, reopening or polling.
  4. Write the brief, tick the free-tier box, press Generate. Cancel is available while it runs.
     A cancelled or late result is never adopted as a draft.
  5. Edit generated narration (it is UNAPPROVED), then press "Save narration edits".
     Pick a library picture for each scene (library upload asks for source and licence).
     Press "Save selection".
  6. Voices: "Preview this voice" makes ONE short preview and counts against the 2-preview budget.
     "Save voices and style" saves voice and style only; it calls nothing.
  7. Shot list: export JSON or Markdown. Missing pictures are listed with prompts. Prompts are not media.
  8. Apply: read the count BEFORE you confirm. "Confirm N and apply" sends exactly that count.
     A changed count is refused with the new number. Nothing is called until you confirm.
     Re-applying an unchanged draft calls nothing and opens the same project.
  9. The project opens in the existing Editor. Generated speech stays unapproved until you listen
     and approve it there. Listening review and owner approval are separate steps.

  Budget: 2 text generations and 2 short previews per QA session, shown on the page. Nothing resets it.
  Keep the same $qa folder for the whole session. Deleting it is a bypass.
